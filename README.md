# Восходы и закаты Москвы

Генерируемый ICS: **https://maks.live/moscow-sun-calendar/moscow.ics**

Страница: https://maks.live/moscow-sun-calendar/

Два события ежедневно: восход солнца и закат. Каждое начинается в расчётный момент и длится 10 минут. «Рассвет» трактуется как восход, а не начало гражданских сумерек. Координаты центра Москвы: 55.7558 N, 37.6173 E, высота наблюдателя 0 м. Расчёт Astral, время округляется до ближайшей минуты. Рельеф, здания и фактическая погода не учитываются.

## Подписка

В Google Calendar в браузере: «Другие календари» → «+» → «Добавить по URL» → вставить ссылку ICS. В Apple Calendar: «Файл» → «Новая подписка на календарь». В Outlook: «Добавить календарь» → «Подписаться из Интернета».

Нужна именно **подписка по URL**: импорт скачанного файла не обновляется. Приложение само определяет частоту загрузки; обновления могут приходить с задержкой. ICS запрашивает обновление раз в сутки. Время хранится в UTC и отображается в часовом поясе приложения; для московских часов выберите Europe/Moscow. Напоминаний нет, события не блокируют занятость.

## Статус автоматизации

Календарь опубликован. Ежедневное обновление пока **не включено**: для публикации GitHub Actions текущей авторизации не хватает scope `workflow`. Готовый workflow сохранён в `automation/calendar.yml`. После `gh auth refresh -h github.com -s workflow` переместите его в `.github/workflows/calendar.yml`, выберите в Settings → Pages источник GitHub Actions и отправьте коммит. Описанный ниже ежедневный режим начнёт работать после активации.

## Обновление и конечный горизонт

GitHub Actions ежедневно в 02:23 UTC (05:23 Москвы) генерирует окно `[сегодня, сегодня + 6 календарных месяцев)`, сохраняет ICS в репозитории и публикует `docs/` на GitHub Pages. Расписание GitHub может запускаться с задержкой. В файле нет бесконечных RRULE: только конечный набор конкретных событий. При обновлении старые даты уходят из файла, новые добавляются. Это скользящая подписка, а не архив. Поведение удаления старых дат зависит от приложения.

UID каждого события зависит от даты и типа, поэтому перекрывающиеся даты не создают дубли. Содержимое прежних событий стабильно. При изменении алгоритма/семантики времени следует повысить SEQUENCE и обновить DTSTAMP. Ежедневные коммиты отражают реальные изменения окна. GitHub может отключать scheduled workflows после 60 дней отсутствия активности в публичном репозитории; при остановке проверяйте Actions и при необходимости включите workflow снова. Если обновление остановится, опубликованный файл останется конечным, новые даты не появятся.

Чтобы остановить продление, отключите workflow в Actions. Чтобы получить фиксированные полгода, скачайте файл или сгенерируйте его с `--start` и импортируйте однократно.

## Локальный запуск

Требуется Python 3.12+.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python generate.py
.venv/bin/python -m unittest -v
# Фиксированное окно; правая граница не включается:
.venv/bin/python generate.py --start 2026-09-23 --months 6 --output /tmp/moscow.ics
```

При переносе в другой репозиторий измените BASE_URL в `generate.py`, URL на странице и в README. В Settings → Pages выберите Source: GitHub Actions. Workflow можно запустить вручную.

## Почему не ежегодное повторение

ICS поддерживает `RRULE:FREQ=YEARLY`, в том числе конечные повторения через `COUNT` или `UNTIL`. Но оно повторяет время на часах и не рассчитывает положение Солнца. В течение года восход и закат меняются ежедневно; на одну календарную дату в разные годы время близкое, но отличается из-за соотношения календарного и солнечного года и високосного цикла. Поэтому здесь рассчитывается каждая дата отдельно.
